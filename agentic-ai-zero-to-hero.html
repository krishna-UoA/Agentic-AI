What is Agentic AI?

Traditional AI models are passive responders—you ask, they answer, done. An agentic AI is different: it can autonomously pursue goals across multiple steps, make decisions, use external tools, and adapt when things go wrong.

Traditional AI vs Agentic AI
The key insight: An agent is not just an LLM. It's an LLM augmented with tools, memory, and a feedback loop that lets it act over multiple steps until it reaches a goal.

The 5 pillars of agentic AI

🧠

Reasoning

Breaks complex goals into sub-tasks and thinks through each step

🔧

Tool Use

Calls external APIs, runs code, searches the web, reads files

💾

Memory

Stores & retrieves information across steps and sessions

🔁

Feedback Loop

Observes results of actions and adjusts its plan accordingly

🎯

Goal Direction

Pursues an objective autonomously without step-by-step human guidance

The Agent Loop

The heart of every agent is the ReAct loop: a repeating cycle of Reasoning and Acting. The agent thinks, takes an action, observes the outcome, and decides what to do next—until the goal is achieved.

The ReAct Agent Loop

Step-by-step example: "Research Tesla stock"

Perceive — Read the goal

Agent receives: "What is Tesla's current stock price and P/E ratio? Should I buy?"

Think — Plan the approach

Agent reasons: "I need current stock data → I'll call the finance API. Then I need the P/E ratio → another lookup. Then I'll synthesize a recommendation."

Act — Call tool #1

Agent calls get_stock_price("TSLA") → receives {"price": 248.50}

Observe — Read result

Agent records the price. Determines it still needs the P/E ratio. Loops back to Think.

Act — Call tool #2

Calls get_fundamentals("TSLA") → receives {"pe_ratio": 65.2, "eps": 3.81}

Done — Return final answer

Agent has all data. Generates a comprehensive answer with price, ratios, and recommendation context. Loop ends.

Python — basic agent loop
def run_agent(goal: str, tools: dict, max_steps: int = 10):
    messages = [
        {"role": "system", "content": "You are an autonomous agent. Reason step-by-step."},
        {"role": "user",   "content": goal}
    ]

    for step in range(max_steps):
        # THINK: call the LLM
        response = llm.chat(messages, tools=tools)

        if response.stop_reason == "end_turn":
            return response.text  # ✓ goal reached

        # ACT: execute the requested tool
        tool_call = response.tool_calls[0]
        result = tools[tool_call.name](**tool_call.args)

        # OBSERVE: add result back to context
        messages.append(response.as_message())
        messages.append({
            "role": "tool",
            "name": tool_call.name,
            "content": str(result)
        })

    return "Max steps reached"

Tool Use & Function Calling

Tools are what transform an LLM from a text predictor into an agent that can affect the world. The LLM decides which tool to call and with what arguments—the runtime actually executes it and returns the result.

Tool Calling Architecture

Defining a tool (JSON Schema)

Tools are described using JSON Schema so the LLM knows exactly what parameters each tool expects.

JSON — tool definition
{
  "name": "get_weather",
  "description": "Get current weather for a city",
  "parameters": {
    "type": "object",
    "properties": {
      "city": {
        "type": "string",
        "description": "City name, e.g. 'Amsterdam'"
      },
      "units": {
        "type": "string",
        "enum": ["celsius", "fahrenheit"]
      }
    },
    "required": ["city"]
  }
}

Memory Systems

LLMs are stateless by default—they have no memory between calls. Agents need multiple types of memory to function over long tasks and across sessions.

The Four Types of Agent Memory

In-Context (Working)

The active prompt window—fast but limited. Everything the agent can "see" right now. Resets each session unless explicitly managed.

External Semantic

A vector database (Pinecone, pgvector, Chroma). Stores embeddings of documents. Agent queries it to retrieve relevant knowledge on demand.

Episodic

Logs of past conversations and task outcomes. Lets the agent learn from experience: "Last time the user asked this, they preferred X format."

Procedural

Hard-coded skills and instructions in the system prompt. Defines the agent's personality, rules, and baseline behaviors.

Python — simple memory manager
from dataclasses import dataclass, field
from datetime import datetime

@dataclass
class AgentMemory:
    # Short-term: conversation window
    messages: list = field(default_factory=list)
    max_tokens: int = 4000

    # Long-term: key-value store
    facts: dict = field(default_factory=dict)

    def add_message(self, role: str, content: str):
        self.messages.append({
            "role": role,
            "content": content,
            "timestamp": datetime.now().isoformat()
        })
        self._trim_to_limit()

    def remember(self, key: str, value):
        self.facts[key] = {"value": value, "saved_at": datetime.now().isoformat()}

    def recall(self, key: str):
        return self.facts.get(key, {}).get("value")

    def _trim_to_limit(self):
        # Keep most recent messages within token budget
        while self._estimate_tokens() > self.max_tokens:
            self.messages.pop(0)  # remove oldest

    def _estimate_tokens(self):
        total = sum(len(m["content"]) // 4 for m in self.messages)
        return total

Planning Strategies

How an agent reasons and decomposes tasks dramatically affects its performance. From simple chain-of-thought prompting to full plan-then-execute frameworks, here are the main strategies.

Planning Strategy Comparison

Chain of Thought (CoT)

  • LLM writes reasoning before answering
  • Prompt: "Think step by step"
  • Best for: logic, math, multi-hop Q&A
  • No external tools needed
  • Fast, low overhead

ReAct (Reason + Act)

  • Interleaves thoughts with tool calls
  • Each thought justifies the next action
  • Best for: research, data tasks, browsing
  • Requires tools/environment
  • The dominant agent pattern

Multi-Agent Systems

Complex tasks benefit from specialized agents working in parallel. A multi-agent system has an orchestrator that breaks down the goal and delegates to specialist worker agents—each with their own tools and memory.

Orchestrator + Specialist Agents Pattern

When to use multi-agent systems

Parallelism

Sub-tasks can run concurrently (e.g. research + coding at the same time), dramatically speeding up complex jobs.

Specialization

Each agent gets a focused system prompt and tool set. A coder agent is better at code than a general-purpose agent.

Context Limits

Break tasks that exceed a single context window across agents—each agent handles its own chunk of work.

Python — orchestrator pattern
async def orchestrate(task: str) -> str:
    # Step 1: Orchestrator plans the work
    plan = await planner_agent(task)
    # plan = ["research topic", "analyze data", "write report"]

    # Step 2: Run sub-agents in parallel
    research, analysis = await asyncio.gather(
        researcher_agent(plan[0]),
        analyst_agent(plan[1])
    )

    # Step 3: Writer synthesizes all results
    report = await writer_agent(
        task=plan[2],
        context={
            "research": research,
            "analysis": analysis
        }
    )
    return report

Build Your First Agent

Let's build a research assistant agent from scratch using the Anthropic API. It can search the web, calculate things, and remember facts across a conversation.

Prerequisites: Python 3.10+, pip install anthropic, an Anthropic API key

Step 1: Define your tools

Python — tool definitions
import anthropic
import json, math, datetime

client = anthropic.Anthropic()

TOOLS = [
    {
        "name": "calculate",
        "description": "Evaluate a math expression. E.g. '2 ** 10' → 1024",
        "input_schema": {
            "type": "object",
            "properties": {
                "expression": {
                    "type": "string",
                    "description": "Python math expression to evaluate"
                }
            },
            "required": ["expression"]
        }
    },
    {
        "name": "get_date",
        "description": "Returns today's date and time",
        "input_schema": {
            "type": "object",
            "properties": {}
        }
    }
]

Step 2: Implement tool handlers

Python — tool execution
def execute_tool(tool_name: str, tool_input: dict) -> str:
    if tool_name == "calculate":
        try:
            # Safe eval: only allow math operations
            result = eval(
                tool_input["expression"],
                {"__builtins__": {}},
                vars(math)
            )
            return str(result)
        except Exception as e:
            return f"Error: {e}"

    elif tool_name == "get_date":
        return datetime.datetime.now().strftime("%A, %B %d %Y, %H:%M UTC")

    return "Unknown tool"

Step 3: The main agent loop

Python — complete agent
def run_agent(user_message: str) -> str:
    messages = [{"role": "user", "content": user_message}]

    while True:
        response = client.messages.create(
            model="claude-sonnet-4-6",
            max_tokens=4096,
            system="You are a helpful research assistant. Use tools when needed.",
            tools=TOOLS,
            messages=messages
        )

        # Add assistant's response to history
        messages.append({"role": "assistant", "content": response.content})

        # Check if done (no more tool calls)
        if response.stop_reason == "end_turn":
            return next(
                b.text for b in response.content
                if b.type == "text"
            )

        # Process all tool calls in this turn
        tool_results = []
        for block in response.content:
            if block.type == "tool_use":
                result = execute_tool(block.name, block.input)
                tool_results.append({
                    "type": "tool_result",
                    "tool_use_id": block.id,
                    "content": result
                })
                print(f"  🔧 {block.name}({block.input}) → {result}")

        # Feed results back to the agent
        messages.append({"role": "user", "content": tool_results})

# Try it!
answer = run_agent("What's 15% compound interest on $10,000 over 7 years?")
print(answer)
Expected output: The agent calls calculate(10000 * (1.15 ** 7)), gets the result, then formats a clear explanation of the compound interest calculation.

RAG solves the LLM's biggest limitation: outdated knowledge. Instead of relying solely on training data, the agent retrieves relevant documents at query time and injects them into the prompt.

Production Considerations

Building a working agent is the first step. Shipping a reliable, safe, cost-effective agent requires addressing several engineering concerns.

🛡️

Safety & Guardrails

Add input/output filters, limit tool permissions, add human-in-the-loop checkpoints for irreversible actions

📏

Evaluation

Build a test suite of tasks with known-good answers. Track success rate, token usage, and latency per run

💸

Cost Control

Set max_steps limits, cache repeated lookups, use smaller models for routing/planning decisions

🔭

Observability

Log every tool call, thought, and action. Use LangSmith, Langfuse, or a custom trace store

🔄

Retry Logic

Handle tool failures gracefully. Let the agent try alternative approaches before giving up

👤

Human-in-the-Loop

Pause and ask for confirmation before high-stakes actions: sending emails, deleting data, making purchases

Production checklist

ConcernQuestion to askSolution
Runaway loopsCan the agent get stuck?Set max_steps, detect repeated actions
Prompt injectionCan user input hijack the agent?Validate inputs, use structured outputs
Data leakageDoes the agent expose PII?Add output filters, PII detection
HallucinationDoes it make up tool results?Require tool calls for factual claims
Token costIs this affordable at scale?Cache, compress history, route to small models
LatencyIs it fast enough for UX?Stream responses, parallelize tool calls
Python — human-in-the-loop checkpoint
HIGH_RISK_TOOLS = {"send_email", "delete_file", "make_payment"}

def execute_tool_safe(tool_name: str, tool_input: dict) -> str:
    if tool_name in HIGH_RISK_TOOLS:
        # Pause and ask for human confirmation
        print(f"\n⚠️  Agent wants to call: {tool_name}")
        print(f"   With args: {json.dumps(tool_input, indent=2)}")
        confirm = input("   Approve? [y/N]: ").strip().lower()

        if confirm != "y":
            return "Action cancelled by user."

    return execute_tool(tool_name, tool_input)
